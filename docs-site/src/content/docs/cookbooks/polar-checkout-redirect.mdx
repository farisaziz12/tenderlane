This cookbook walks through wiring Polar.sh into Tenderlane: server adapter, browser provider, and a catalog entry that maps your SKU to Polar's pre-created product ID.

Polar is **redirect-only** in Tenderlane today. The iframe embedded flow is not built (it is a whole-page iframe, not a field-level form like Stripe's Payment Element).

Two Polar constraints shape everything below:

- **One product, quantity 1, per checkout.** Polar's `products` field is a list the customer chooses one from, not a cart, and it has no quantity. The adapter rejects a cart with several items or a quantity above 1 with a `CatalogError` (HTTP 400) instead of charging for something else.
- **No price override.** Polar charges the product's own price. Tenderlane sends only the product ID.

## What you will build

- A checkout page that routes to Polar
- A server endpoint that creates Polar checkouts via `@polar-sh/sdk`
- A catalog that declares Polar product IDs alongside any other PSPs you use

## Prerequisites

- Node.js 18+
- A React project with a server-side API capability (Next.js App Router, Remix, etc.)
- A [Polar account](https://polar.sh) (sandbox is fine for testing)
- One pre-created product in your Polar org (Polar is product-first: you cannot pass arbitrary line items at checkout time)

## 1. Create a Polar sandbox token

1. Sign up at [sandbox.polar.sh](https://sandbox.polar.sh) (production tokens live at [polar.sh](https://polar.sh))
2. Create an organization and add at least one product
3. Note your **organization ID** and create an **Organization Access Token** (OAT) in the dashboard
4. Note the product ID of the SKU you want to sell

Sandbox and production are different hostnames (`sandbox-api.polar.sh` vs. `api.polar.sh`), not the same host with different key prefixes, so the adapter takes an explicit `server` option.

## 2. Install packages

```bash
pnpm add tenderlane @polar-sh/sdk
```

`@polar-sh/sdk` is only needed on the server side. The browser bundle of `tenderlane/polar` imports zero bytes of it.

## 3. Set up environment variables

```bash title=".env"
POLAR_ACCESS_TOKEN=polar_oat_...
POLAR_ORGANIZATION_ID=org_...
POLAR_PRODUCT_ID=...
NEXT_PUBLIC_POLAR_ORG_ID=org_...
```

## 4. Build the server endpoint

The cleanest setup uses `createPolarCatalog`. The catalog calls `polar.products.get(...)` at submit time, so the canonical price lives in Polar, not in your code or database.

```ts title="app/api/payments/polar/route.ts"
import { createTenderlaneHandler } from 'tenderlane/server';
import {
  polarServerAdapter,
  createPolarCatalog,
} from 'tenderlane/polar/server';

const polarCatalog = createPolarCatalog({
  accessToken: process.env.POLAR_ACCESS_TOKEN!,
  organizationId: process.env.POLAR_ORGANIZATION_ID!,
  server: 'sandbox', // or 'production'
  skus: {
    'premium-plan': { productId: process.env.POLAR_PRODUCT_ID! },
  },
});

const handler = createTenderlaneHandler({
  providers: [
    polarServerAdapter({
      accessToken: process.env.POLAR_ACCESS_TOKEN!,
      organizationId: process.env.POLAR_ORGANIZATION_ID!,
      server: 'sandbox',
    }),
  ],
  catalogs: {
    polar: polarCatalog,
  },
});

export const POST = handler.POST;
```

The catalog reads each SKU's mapped Polar product at resolve time, picks the first fixed-amount price (or a specific `priceId` if you declared one on the SKU config), and populates `providerRefs.polar.productId` on the resolved item. The adapter then sends `products: [productId]` to Polar's checkout API, and Polar charges the product's own price.

The optional `priceId` on a SKU only selects which of the product's prices the catalog reports as `unitAmount` for display. It is not sent to Polar and does not change what Polar charges.

If your client uses `createRemoteCatalog` for preview, also wire up the resolve route:

```ts title="app/api/payments/polar/resolve/route.ts"
// `handler` is the object created above; move it to a shared module to import it here.
export const POST = handler.resolve;
```

`resolve` uses the handler's top-level `catalog`, not `catalogs.polar`, so pass the Polar catalog as `catalog` as well if you use this route.

## 5. Build the React checkout page

```tsx title="app/checkout/page.tsx"
'use client';

import { createRulesRouter } from 'tenderlane';
import { TenderlaneProvider, useTenderlaneCheckout } from 'tenderlane/react';
import { polarProvider } from 'tenderlane/polar';

const polar = polarProvider({
  organizationId: process.env.NEXT_PUBLIC_POLAR_ORG_ID!,
  serverEndpoint: '/api/payments/polar',
});

const routing = createRulesRouter({
  rules: [],
  fallback: {
    provider: 'polar',
    flow: 'checkout-session',
    paymentMethods: ['card'],
  },
});

const context = { currency: 'usd' } as const;

export default function CheckoutPage() {
  return (
    <TenderlaneProvider config={{ context, providers: [polar], routing }}>
      <PayButton />
    </TenderlaneProvider>
  );
}

function PayButton() {
  const checkout = useTenderlaneCheckout();
  const busy = checkout.status === 'submitting' || checkout.status === 'redirecting';
  return (
    <>
      {checkout.error && <p>{checkout.error.message}</p>}
      <button
        disabled={!checkout.canSubmit || busy}
        onClick={() =>
          checkout.submit({
            // One item, quantity 1: a Polar checkout sells one product.
            items: [{ sku: 'premium-plan', quantity: 1 }],
            successUrl: 'https://example.com/success',
            cancelUrl: 'https://example.com/cancel',
          })
        }
      >
        {busy ? 'Redirecting...' : 'Pay with Polar'}
      </button>
    </>
  );
}
```

Note that `submit()` posts only `{ items, successUrl, cancelUrl }`, with no `unitAmount` anywhere. The server runs its own `catalog.resolve()`. After the checkout is created the client status is `redirecting`, not `success`. `cancelUrl` is required by the input type but Polar has no equivalent, so it is not sent. See the [Catalog concepts page](/docs/concepts/catalog) for the full price-integrity contract.

## 6. Test the redirect

1. Run `pnpm dev`
2. Open `/checkout`, click **Pay with Polar**
3. You should be redirected to `sandbox.polar.sh/c/...` for the hosted checkout
4. Complete the test payment; you return to your `successUrl`

## Fulfillment via webhooks (not the redirect)

**The redirect to `successUrl` is UX only. It is not authoritative for fulfillment.** Polar's source of truth for "was this paid?" is webhooks, which implement the [Standard Webhooks](https://www.standardwebhooks.com/) spec. The relevant events are `checkout.created`, `checkout.updated`, `order.created`, `order.paid`.

Tenderlane does not ship a Polar webhook verifier. Wire that up directly with the `validateEvent` helper from `@polar-sh/sdk/webhooks`.

## Mixing Polar with Stripe in the same app

Because the catalog is provider-agnostic, you can route to either PSP from the same checkout. Declare `providerRefs` for both on each SKU:

```ts
const catalog = defineCatalog({
  async resolve(items, context) {
    return items.map((item) => ({
      sku: item.sku,
      quantity: item.quantity,
      name: 'Pro Plan',
      unitAmount: 2900,
      currency: context.currency ?? 'usd',
      providerRefs: {
        stripe: { priceId: 'price_xyz' },          // Stripe charges this Stripe Price
        polar:  { productId: 'polar_prod_abc' },   // Polar charges this product's own price
      },
    }));
  },
});
```

Then routing rules pick the PSP based on context (country, currency, experiment variant, etc.), and the adapter reads the ref it understands. Keep the Polar product's price equal to the `unitAmount` you declare, because Polar ignores `unitAmount`. Route carts with several items or quantities above 1 to Stripe: Polar rejects them. See the [Country-based routing cookbook](/docs/cookbooks/country-based-routing) for a full multi-PSP example.

## What is not built

- **Multi-item carts and quantities**: one product, quantity 1 per checkout
- **Price overrides**: Polar charges the product's own price
- **Iframe embedded checkout** (`@polar-sh/checkout`)
- **Subscriptions**: Tenderlane is one-off only across all providers
- **Webhook verification helper**: use `@polar-sh/sdk/webhooks` directly
- **Multi-currency**: the adapter declares `currencies: ['usd']`
