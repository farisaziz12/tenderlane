Core has no list of supported providers. A provider is two small objects, one for the browser and one for the server, and everything they need is exported from `@tenderlane/core/adapters`. The Stripe and Polar packages have no access to anything else.

This guide builds an adapter for a made-up PSP called Acme with a hosted checkout page.

## Package layout

Publish your adapter as its own package with `@tenderlane/core` as a peer dependency. Keep the browser and server entries apart so the PSP's server SDK and secret key cannot reach a client bundle.

```json title="package.json"
{
  "name": "tenderlane-acme",
  "type": "module",
  "sideEffects": false,
  "exports": {
    ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" },
    "./server": { "types": "./dist/server.d.ts", "import": "./dist/server.js" }
  },
  "peerDependencies": {
    "@tenderlane/core": ">=0.1.0-alpha.0"
  }
}
```

## The browser provider

The browser provider tells the client which payment methods exist and what to do on submit. For a redirect flow, submit asks your app's Tenderlane handler to create the checkout and then navigates to it.

```ts title="src/index.ts"
import { defineBrowserProvider, requestProviderAction } from '@tenderlane/core/adapters';

export interface AcmeProviderOptions {
  /** URL of the app's Tenderlane handler. */
  serverEndpoint: string;
}

export function acmeProvider(options: AcmeProviderOptions) {
  return defineBrowserProvider({
    id: 'acme',
    capabilities: {
      provider: 'acme',
      flows: ['checkout-session'],
      paymentMethods: ['card'],
      supports: { redirect: true },
    },
    getAvailablePaymentMethods: () => [
      { id: 'card', label: 'Card', type: 'card', provider: 'acme' },
    ],
    async submit(input, route) {
      const result = await requestProviderAction({
        endpoint: options.serverEndpoint,
        provider: 'acme',
        action: 'checkout',
        input,
        route,
      });
      if (result.url) window.location.href = result.url;
      return result;
    },
  });
}
```

`defineBrowserProvider` is an identity function. It adds the `~types` property used for inference and keeps `'acme'` as a string literal, so `InferProviderId<typeof provider>` is `'acme'`.

`requestProviderAction` sends `{ provider, action, payload, paymentMethods }`, the format the handler expects, and throws a `ProviderError` on a non-2xx answer. It does not navigate. That is the provider's decision.

Return the result as the PSP reported it. The client sets `redirecting` when a result has a `url` and is not `complete`, `pending` when it has neither, and `success` only for `complete`. A `failed` or `expired` result becomes an error.

### Inline flows

For a flow that renders payment fields in your page, also implement `createSession`. The client calls it from `prepare()` and stores what you return as `providerSession`. `submit()` then confirms that session. See the [state machine](/docs/concepts/state-machine).

## The server adapter

The server adapter receives a payload whose `items` were already resolved by the app's catalog. Read prices from there and from nowhere else.

```ts title="src/server.ts"
import { defineServerAdapter, ProviderError } from '@tenderlane/core/adapters';

export interface AcmeServerConfig {
  secretKey: string;
}

export function acmeServerAdapter(config: AcmeServerConfig) {
  return defineServerAdapter({
    id: 'acme',
    actions: ['checkout'],
    async handle(action, payload) {
      const response = await fetch('https://api.acme.example/v1/checkouts', {
        method: 'POST',
        headers: {
          authorization: `Bearer ${config.secretKey}`,
          'content-type': 'application/json',
        },
        body: JSON.stringify({
          lines: payload.items.map((item) => ({
            name: item.name,
            amount: item.unitAmount,
            currency: item.currency,
            quantity: item.quantity,
          })),
          return_url: payload.successUrl,
        }),
      });
      if (!response.ok) {
        throw new ProviderError(`Acme answered ${response.status}`, 'acme');
      }
      const checkout = await response.json();
      return { provider: 'acme', id: checkout.id, status: 'open', url: checkout.url };
    },
  });
}
```

Inside `handle`, `action` is typed as the union of the names in `actions`.

## Rules for adapter authors

- **Prices come from `payload.items`.** Never read an amount from anything else in the payload.
- **`payload.providerOptions` is server configuration.** The handler drops whatever the browser sent and passes only what the app set in the handler's `providerOptions`. If you merge it into the PSP request, apply it before the fields that carry money, not after.
- **Reject what the PSP cannot represent.** If the PSP has no cart or no quantity, throw a `CatalogError` for a cart it cannot charge correctly. The Polar adapter does this for multi-item carts. A `CatalogError` becomes a 400 with your message.
- **Throw `ProviderError` for PSP failures.** The handler answers 5xx with a generic body and passes the error to the app's `onError`. PSP error text can contain internals.
- **Use `providerRefs` for native ids.** A catalog item can carry `providerRefs.acme` with your product or price id. Prefer it over inline amounts when the PSP supports it.
- **Match errors by `code`.** Use `hasErrorCode(error, 'CATALOG_ERROR')` from `@tenderlane/core` instead of `instanceof` when an error may come from another package. Two copies of core in one process have distinct classes.

## Using it

A routing rule can target any provider id.

```ts title="routing.ts"
import { createRulesRouter } from '@tenderlane/core';

export const routing = createRulesRouter({
  rules: [
    { id: 'br-acme', when: { country: 'BR' }, use: { provider: 'acme', flow: 'checkout-session' } },
  ],
  fallback: { provider: 'stripe', flow: 'checkout-session' },
});
```

Register `acmeProvider(...)` in the client's `providers` and `acmeServerAdapter(...)` in the handler's `providers`.
