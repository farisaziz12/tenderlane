This guide walks you through building a complete checkout flow: a React page that routes payments through Stripe, backed by a server endpoint that looks up the price and creates Stripe Checkout Sessions. By the end, you will have a working checkout that you can test with Stripe's test card.

## Prerequisites

- Node.js 18+
- A [Stripe test account](https://dashboard.stripe.com/register) with API keys
- A React project (Next.js, Vite, or similar)

## 1. Set up environment variables

Create a `.env` file (or `.env.local` for Next.js) with your Stripe keys:

```bash
STRIPE_SECRET_KEY=sk_test_...
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...
```

:::tip
You can find your test API keys in the [Stripe Dashboard](https://dashboard.stripe.com/test/apikeys) under Developers > API keys. Make sure you are in test mode.
:::

## 2. Create the server endpoint

The server endpoint receives checkout requests from Tenderlane, resolves the price of each item from a catalog, and creates Stripe Checkout Sessions. This example uses Next.js App Router, but the handler works with any framework that supports the Web `Request`/`Response` API.

```ts title="app/api/checkout/route.ts"
import { createInlineCatalog } from '@tenderlane/core';
import { createTenderlaneHandler } from '@tenderlane/core/server';
import { stripeServerAdapter } from '@tenderlane/stripe/server';

// The server owns the price. The browser only sends a SKU and a quantity.
const catalog = createInlineCatalog({
  'premium-widget': {
    name: 'Premium Widget',
    pricing: { amount: 2500, currency: 'usd' },
  },
});

const handler = createTenderlaneHandler({
  providers: [
    stripeServerAdapter({
      secretKey: process.env.STRIPE_SECRET_KEY!,
    }),
  ],
  catalog,
});

export const POST = handler.POST;
```

That is the entire server-side setup. `createTenderlaneHandler` returns `{ POST, resolve }`. `POST` validates the request, resolves `items` against the catalog, dispatches to the provider adapter named in the `provider` field, and returns a normalized `CheckoutResult`.

:::caution
A request without a catalog is rejected. The browser never sends an amount: see the [Security model](/docs/concepts/security-model).
:::

## 3. Build the checkout page

```tsx title="app/checkout/page.tsx"
'use client';

import { useState } from 'react';
import { TenderlaneProvider, useTenderlaneCheckout } from '@tenderlane/react';
import { createRulesRouter } from '@tenderlane/core';
import { stripeProvider } from '@tenderlane/stripe';

const stripe = stripeProvider({
  publishableKey: process.env.NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY!,
  serverEndpoint: '/api/checkout',
});

const router = createRulesRouter({
  rules: [
    {
      id: 'eu-checkout',
      when: { country: { in: ['DE', 'FR', 'IT', 'ES', 'AT', 'NL'] } },
      use: { provider: 'stripe', flow: 'checkout-session', paymentMethods: ['card', 'sepa_debit'] },
    },
    {
      id: 'ch-checkout',
      when: { country: 'CH' },
      use: { provider: 'stripe', flow: 'checkout-session', paymentMethods: ['card', 'twint'] },
    },
    {
      id: 'default-checkout',
      when: {},
      use: { provider: 'stripe', flow: 'checkout-session', paymentMethods: ['card'] },
    },
  ],
  fallback: { provider: 'stripe', flow: 'checkout-session', paymentMethods: ['card'] },
});

export default function CheckoutPage() {
  const [country, setCountry] = useState('US');

  const config = {
    context: { country, currency: 'usd', amount: 2500 },
    providers: [stripe],
    routing: router,
  };

  return (
    <TenderlaneProvider config={config}>
      <h1>Checkout</h1>
      <label>
        Country:{' '}
        <select value={country} onChange={(event) => setCountry(event.target.value)}>
          <option value="US">United States</option>
          <option value="DE">Germany</option>
          <option value="CH">Switzerland</option>
          <option value="FR">France</option>
        </select>
      </label>
      <CheckoutForm />
    </TenderlaneProvider>
  );
}

function CheckoutForm() {
  const checkout = useTenderlaneCheckout();

  if (checkout.status === 'evaluating') return <p>Loading...</p>;

  return (
    <div>
      {checkout.error && <p>Error: {checkout.error.message}</p>}
      <p>Provider: {checkout.selectedProvider}</p>
      <p>Payment methods: {checkout.paymentMethods.map((method) => method.label).join(', ')}</p>

      <button
        disabled={!checkout.canSubmit || checkout.status === 'submitting'}
        onClick={() =>
          checkout.submit({
            items: [{ sku: 'premium-widget', quantity: 1 }],
            successUrl: window.location.origin + '/success',
            cancelUrl: window.location.origin + '/cancel',
          })
        }
      >
        {checkout.status === 'submitting' || checkout.status === 'redirecting'
          ? 'Redirecting...'
          : 'Pay $25.00'}
      </button>
    </div>
  );
}
```

## 4. Test it

Start your development server and navigate to your checkout page.

1. Select **United States**: "Credit or debit card" is the only payment method
2. Switch to **Germany**: SEPA Direct Debit appears alongside card
3. Switch to **Switzerland**: TWINT appears alongside card
4. Click **Pay $25.00**: you are redirected to Stripe's hosted checkout page
5. Use card number `4242 4242 4242 4242` with any future expiry date and any CVC

:::note
The payment methods shown in the UI update instantly when you change the country. This is Tenderlane's reactive routing in action: the routing rules re-evaluate against the new context, the selected route changes, and the checkout UI updates automatically via `useSyncExternalStore`.
:::

## What just happened?

Here is the sequence of events when you change the country dropdown:

1. React state update: `setCountry('CH')`
2. `TenderlaneProvider` detects the context change and calls `client.updateContext({ country: 'CH', ... })`
3. The rules router evaluates the new context against the rules in order
4. Rule `ch-checkout` matches (`country: 'CH'`), selecting `['card', 'twint']` as payment methods
5. The client enters the `ready` state with the new route
6. `useTenderlaneCheckout` triggers a re-render with the updated payment methods
7. The UI shows "Credit or debit card, TWINT"

When you click Pay:

1. `checkout.submit()` calls the Stripe browser provider's `submit` method
2. The provider sends a `POST` to `/api/checkout` with `{ provider: 'stripe', action: 'checkout', payload: { items: [{ sku, quantity }], successUrl, cancelUrl } }`. No amount is sent.
3. The server handler validates the items and resolves them against the catalog to get the name, amount and currency
4. The handler dispatches to the Stripe server adapter, which creates a Stripe Checkout Session and returns the redirect URL
5. The client status becomes `redirecting` and the browser leaves for Stripe's hosted checkout page

`redirecting` is not `success`. The payment has not happened yet when the browser leaves, so nothing on the client can tell you it was paid. Confirm payment on your server from the provider's webhook. Tenderlane does not ship webhook helpers yet.
